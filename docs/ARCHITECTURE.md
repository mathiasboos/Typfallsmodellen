# Architecture

## Shape

```
Typfallsmodellen-yyyy-mm-dd.xlsb   (published by Pensionsmyndigheten)
        |
        |  tools/extract   Python, run once a year by a developer
        v
  packages/data/           JSON + a Float64 binary + manifest.json (committed)
        |
        v
  packages/engine/         TypeScript port of the VBA; runs in Node and the browser
        |                    `-- tools/compare  CLI: engine vs. Excel golden files
        v
  apps/web/                static site
```

## Why the calculation runs in the browser

One model run is about 90 age iterations of pure arithmetic — sub-millisecond in JavaScript.
There is nothing to gain from a server, and real things to lose: hosting cost, an operational
surface, and a copy of whatever people type about their own finances. A static build keeps all
three at zero.

## Why the data is committed rather than built

`packages/data` is generated, but checked in. It makes the build reproducible without LibreOffice
in CI, and it turns the yearly update into a reviewable diff: you can see that the prisbasbelopp
moved from 59 200 to 60 400 and that nothing else did.

## Why the engine is a separate package

`packages/engine` has no DOM and no framework dependency, so the same code runs in the browser,
in Node for unit tests, and in the batch comparison CLI that checks it against Excel. It is the
part with the longest life; the UI around it can be replaced without touching it.

## What the extraction pipeline does

`tools/extract` reads the workbook twice over. Values come from the `.xlsb` directly via pyxlsb.
Formulas need a detour — `.xlsb` stores them as parsed token streams — so LibreOffice converts
the workbook to `.xlsx` once and openpyxl reads them from there.

That formula pass is what makes `lastActualYear` exact. A series' decided values are typed into
the sheet as literals and its projection begins at the first formula cell, so "last literal year"
*is* "last actual year" — no heuristic, no reviewer judgement. See
[PROJECTION-RULES.md](PROJECTION-RULES.md).

It also dumps the VBA source to `reference/vba/`, which is what makes next year's release
diffable.

## What lives where

| Concern | Home |
|---|---|
| Yearly *data* (indices, basbelopp, mortality, tax rates) | `packages/data`, regenerated by script |
| Yearly *rules* (a new grundavdrag, a changed contribution rate) | `packages/engine`, ported by hand |
| Projection past the last actual year | `packages/engine/src/data/projection.ts` |
| VBA arithmetic semantics | `packages/engine/src/vba/` |
| Form options, defaults, translations, glossary | `packages/data`, extracted from the workbook |

The split matters: data changes every year and should never need a developer to read a
spreadsheet; rule changes every year and always needs one.
